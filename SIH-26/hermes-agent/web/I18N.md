# Offline dashboard localization

The dashboard's existing `src/i18n/*.ts` catalogs remain the source of truth for key-based UI text. INDRA-specific and legacy hard-coded page copy is covered by the prebuilt `src/i18n/ui-generated/*.json` bundles. The browser loads only the selected bundle; it never sends page content to a translation service. The language selector persists the chosen locale locally.

To regenerate the supplemental bundles on a developer machine with a local OpenAI-compatible model:

```powershell
npm run i18n:audit
node scripts/generate-ui-locales.mjs
npm run i18n:verify
```

The generator accepts only a loopback endpoint (`INDRA_TRANSLATION_ENDPOINT`, default `http://127.0.0.1:8100/v1/chat/completions`). It resumes from saved JSON checkpoints. `INDRA_TRANSLATION_MODEL` defaults to `qwen3.5-4b`. No model or translation package is needed on end-user machines; generated JSON is bundled into the web build.

Machine translations are drafts. Before release, a fluent reviewer should check each locale, particularly security wording, action buttons, error states, and right-to-left layouts. Keep commands, paths, code, model identifiers, user messages, filenames, and session titles in their source language. Mark additional user-controlled regions `translate="no"`. New shared copy should go into the normal key-based catalogs rather than relying on the supplemental DOM localizer.
